# Навантажувальне тестування

## Сценарій

Файл `loadtest/notes.js`, інструмент k6.

Профіль «мало записів, багато читань». Кожен віртуальний користувач у циклі виконує:

1. `POST /notes` — створює нотатку від свого імені (`user-<номер>`);
2. 9 читань:
   - 4 × `GET /notes` — список останніх 50 нотаток;
   - `GET /notes/{id}` — щойно створена нотатка;
   - 3 × `GET /notes/{id}` — випадкові нотатки зі списку;
   - `GET /authors/{author}` — дані автора (кількість нотаток, час останньої);
3. пауза 1 с.

Співвідношення запис : читання = 1 : 9.

Фази:

| Фаза | Тривалість | Користувачі |
|---|---|---|
| Наростання | 2 хв 30 с | 0 → N |
| Стале навантаження | 5 хв | N |
| Спад | 2 хв | N → 0 |

Разом 9,5 хв.

## Запуск

Встановити k6: `winget install GrafanaLabs.k6`. Потім з кореня репозиторію:

```
k6 run -e BASE_URL=http://<адреса ALB> -e USERS=40 -e RESULT=cache-on loadtest/notes.js
```

Адреса береться з `terraform -chdir=infra output public_url`. Усі параметри описані в `loadtest/README.md`.

## Підбір N

Одна копія має 0.25 vCPU. N підбирали пробними запусками так, щоб на сталому навантаженні середній CPU перевищив 60% і з'явилася хоча б одна нова копія, але частка помилок лишалася нижчою за 1%.
