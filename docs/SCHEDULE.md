# Масштабування за розкладом

## Що зроблено

`infra/schedule.tf` — дві заплановані дії Application Auto Scaling для сервісу застосунку:

| Дія | Розклад (Europe/Kyiv) | Мінімум копій | Максимум копій |
|---|---|---|---|
| `notes-day` | `cron(0 8 * * ? *)` — щодня о 08:00 | 2 | 3 |
| `notes-night` | `cron(0 22 * * ? *)` — щодня о 22:00 | 1 | 3 |

Розклад змінює лише межі. Усередині них далі працює звичайна політика за CPU з завдання 1: удень копій 2 або 3, уночі 1–3.

Вмикається змінною `schedule_enabled` (за замовчуванням `false`, щоб не заважати демонстрації завдань 1–4, де мінімум має бути 1):

```
terraform apply -var schedule_enabled=true
```

Оскільки розклад сам змінює `min_capacity`, в `aws_appautoscaling_target.app` додано `ignore_changes = [min_capacity]`. Інакше наступний `terraform apply` повертав би мінімум до 1 посеред дня.

Перевірити, що дії створено:

```
aws application-autoscaling describe-scheduled-actions --service-namespace ecs
```

## Чому вночі 1, а не 0

ECS Fargate технічно дозволяє desired count = 0. Але за ALB це означає, що на перший нічний запит балансувальник відповість `503`, бо цілей немає. Target tracking за CPU не підніме сервіс з нуля: при 0 копіях немає метрики CPU. Щоб «прокидатися» від запиту, потрібен механізм на кшталт Cloud Run, Azure Container Apps або Lambda, де платформа сама тримає запит, поки стартує контейнер. Для ECS + ALB мінімум 1 — найменше безпечне значення, тож холодний старт тут не вимірюється.

## Розрахунок місячної економії

Ціни Fargate, eu-central-1, Linux/x86 (перевірити актуальні на aws.amazon.com/fargate/pricing):

- vCPU — $0.04656 за годину;
- пам'ять — $0.00511 за ГБ на годину.

Одна копія (0.25 vCPU, 0.5 ГБ): 0.25 × 0.04656 + 0.5 × 0.00511 = **$0.0142 за годину**.

Місяць — 30 днів. Порівнюємо з варіантом, коли для денного навантаження мінімум 2 тримається цілодобово:

| Варіант | Копій-годин на добу | Копій-годин на місяць | Вартість на місяць |
|---|---|---|---|
| Цілодобово мінімум 2 | 2 × 24 = 48 | 1 440 | $20.44 |
| Удень 2 (14 год), уночі 1 (10 год) | 2 × 14 + 1 × 10 = 38 | 1 140 | $16.18 |
| Удень 2, уночі 0 (гіпотетично) | 2 × 14 = 28 | 840 | $11.93 |

**Економія з розкладом: 300 копій-годин = $4.26 на місяць (21%).** З нічним нулем було б $8.51 (42%), але, як пояснено вище, з ALB це неприйнятно.

Рахуються лише мінімальні копії. Додаткові копії, які додає політика за CPU під навантаженням, в обох варіантах однакові.

## Контекст

Для цього навчального проєкту економія невелика в абсолютних числах, бо фіксовані витрати більші за вартість контейнерів:

- NAT Gateway — ~$0.052/год ≈ $37/міс;
- ALB — ~$0.027/год ≈ $19/міс;
- RDS db.t4g.micro — ~$0.018/год ≈ $13/міс.

Розклад має сенс, коли копій багато: для сервісу з 20 копіями вдень і 5 уночі той самий підхід зекономив би вже сотні доларів на місяць.
